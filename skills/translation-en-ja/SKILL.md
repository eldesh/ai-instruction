# 翻訳のメタ戦略

翻訳する際の手順を以下に定める。
その際常に[#技術文書の和訳](技術文書の和訳)または[#技術文書の英訳](技術文書の英訳)に沿うようにする。

1. 前後のつながりなどを特別考慮することをせず翻訳(抄訳)する(最初から完璧なものを目指さない)。
2. 文化的に通じない慣習や風俗に依存した記述は字義どおりに訳し、訳注を加える。
  - 例: 慣用句、特定テレビ番組の内容など
3. 全体を見直し、文の接続が不自然な部分を原文の前後を考慮しながら再度翻訳する。
4. 文が不自然な場合、１文を複数の文に分割したり、逆に複数の文を１つにまとめることも考慮し再度全体を見直す。
5. 一貫性を検査、修正する
  1. 同種の文が同様に訳されているかを確認する。
    - 悪い例: 本筋から外れた複数のコラムが異なるスタイルに訳されている
  2. 同種の単語が同様に訳されているかを確認する。
    - 悪い例: Chapter, Section が場所によって「節」や「チャプター」になっている
  3. です/ますなど書き手や文中の登場人物の語り口が一貫するようにする。
    - 悪い例: 前半では～だ/である口調だが、後半は～です/ます口調になっている
6. 訳文全体を再確認し、問題がある場合は2.に戻る。


# 技術文書の和訳

英語で書かれた技術的な内容の文章を和訳するときは以下の規範に従う。

- 慣例的にカタカナで表記される単語は、カタカナを使用する。
- 確立された日本語訳が不明な場合は、アルファベット表記のままにする。
- 自然な日本語に翻訳できない場合は、たとえ日本語として多少不自然であっても、意味をすべて忠実に再現することを優先する。


## 翻訳調の比喩と擬人化の禁止

英日翻訳では、直訳すると特に以下のようなケースで看過しづらい不自然な日本語になる。

- 英語慣用句の直訳：英語の技術文では carry / open / expose / live / land などの比喩的用法が慣用句として定着しており、比喩として意識されない。これを日本語の対応語に直訳すると、日本語では慣用化していないため、字義どおりに読める奇妙な生きた比喩になる。
  - 悪い例：「ベクトルが選好を運ぶ」（carry）。良い例：「選好がベクトルとして表現される」「ベクトルに反映される」。
  - 悪い例：「この問いは開かれている」（open question）。良い例：「この問いにはまだ答えが出ていない」「未解決である」。
  - 悪い例：「推敲の軸が露出する」（expose）。良い例：「推敲の軸が線形に取り出せる」。
  - 悪い例：「この情報は残差ストリームに住んでいる」（live in）。良い例：「残差ストリームに含まれる」。

- 無生物主語構文の直輸入：英語では無生物主語の他動詞文が普通だが、そのまま日本語にすると、モデル、データ、ベクトル、損失といった抽象物が意思を持って振る舞う擬人化になる。日本語では、人か処理を主体に戻すか、「〜から分かる」「〜に含まれる」の形に言い直す。
  - 悪い例：「モデルは文体を知っている」。良い例：「モデルの出力には文体の一貫性がある」など、確認できる事実として書く。
  - 悪い例：「データが語るのは〜である」。良い例：「データから分かるのは〜である」。

- 研究者の話し言葉の混入：口頭議論で流通する動詞（「効く」「刺さる」「筋がいい」など）は、話し言葉としては通じるが、書き言葉の技術文書では俗語である。効果や見込みの内容を具体的に書く。
  - 悪い例：「規範スキルが効く」。良い例：「規範スキルを与えると、生成される文章が読者の望むスタイルに近づく」
  - 悪い例：「この手法は筋がいい」。良い例：「この手法は〜という理由で有望である」。


上記のようなケースで発生した問題点は以下の手順で修正を試みる。

1. その述語を初めて見る読者が字義どおりの動作（運ぶ、開く、住む）を想像しうるなら、翻訳調の比喩を疑う。
1. 動作の主体と対象を具体語で言い直せるか試す。
  - 言い直せるなら、その言い直しをそのまま書く。
  - 言い直せないなら、その文は指す内容が特定できていないので、主張として成立していない。内容を再確認し、自然な日本語に書き直す。
